# KREPLIN minigame redesigns (approved by owner)

Every minigame is rebuilt on `ui-draft/minigames/mgkit.js` (MGKit). Rules for all:
- **Portrait first** (180x320 logical px) unless noted; must be fully playable by touch on a 390x844 phone AND by mouse/keyboard on a laptop.
- **Same outcome contract** as the current function: same return values / same state effects / same story branch. The new module exposes a function with the same name+signature (or an adapter) so the caller in `src/` needs at most a one-line change.
- **No soft-locks**: use MGKit's Give-up (after N fails or seconds) which resolves with the existing lose outcome; after 3 fails offer an easier retry where noted.
- **Frame-rate independent** (MGKit gives dt). No hover-only affordances. Remove all listeners on end (MGKit does its own).
- **Pixel art via PixelLab** (`NODE_USE_ENV_PROXY=1 node tools/pixellab.js art/specs/<file>.json`, see tool header for spec format; transparent sprites with `"nobg": true`; sizes 16–128px). Put sprites in `art/raw/mg-<game>-*.png`. Budget ≈ 20 generations per game; animate cheaply (2–4 generated key frames, or procedural squash/stretch/rotation/palette tricks). Review each sprite visually (render a contact sheet with `node tools/contact.js out.png mg-<game>`) and regenerate failures.
- Tone: the game's crude absurdist comedy. Keep all existing text strings; you may add short new UI strings/banners in the same voice.
- Visual language: matches `ui-draft/kui.css` tokens (Saints red #d71920, ink #0d1016, gold #f2c14e, Pixelify Sans for text).

## Build process
Build each game as a standalone module `ui-draft/minigames/<game>.js` + demo page `ui-draft/minigames/<game>-demo.html` (loads mgkit.js + the module, runs the game with a fake `S` and logs the result). Verify with Playwright at 390x844 (touch emulation, `hasTouch:true`) and 1366x860 (mouse/keyboard): play it scripted to both a win and a loss, screenshot, check no page errors. Integration into `src/` happens later in one pass.
